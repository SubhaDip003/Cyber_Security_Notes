# **What is Cloud Computing?**

**Cloud Computing** is the delivery of computing services such as servers, storage, databases, and networking over the internet. Users can access these resources whenever needed and pay only for what they use.

### **Key Characteristics of Cloud Computing**

1. **On-Demand Self-Service:** Users can create and manage cloud resources, such as virtual machines and storage, whenever they need them without contacting the service provider.

2. **Rapid Elasticity:** Cloud resources can be increased or decreased quickly based on workload requirements.

3. **Resource Pooling:** Cloud providers share physical hardware among multiple customers (tenants). Technologies like hypervisors keep their resources separated.

4. **Measured Service (Pay-as-you-go):** Cloud usage is monitored and measured. Customers pay only for the resources they consume, such as computing power, storage, or network usage.

### **Simple Example**

Suppose you need a server for your project. Instead of buying a physical server, you can rent a virtual server from AWS, Microsoft Azure, or Google Cloud. You can increase its capacity whenever required and pay only for what you use.

**In simple words:** Cloud computing allows us to use computing resources over the internet without purchasing and maintaining our own physical hardware.

# Hyperscalers

**Hyperscalers** are large cloud service providers that offer computing resources such as virtual machines, storage, databases, networking, and security services on a massive scale.

The three major cloud service providers are:

1. **AWS (Amazon Web Services)**
    
2. **Microsoft Azure**
    
3. **GCP (Google Cloud Platform)**
    

### **Comparison of Major Cloud Providers**

|Capability|AWS|Microsoft Azure|Google Cloud (GCP)|
|---|---|---|---|
|**Compute**|Amazon EC2|Azure Virtual Machines|Compute Engine|
|**Object Storage**|Amazon S3|Azure Blob Storage|Cloud Storage|
|**Identity Management**|AWS IAM & Identity Center|Microsoft Entra ID|Cloud IAM|
|**Key Management**|AWS KMS|Azure Key Vault|Cloud KMS|
|**Core Strength**|Wide range of cloud services|Strong enterprise and hybrid cloud integration|Strong in Kubernetes, data analytics, and AI|

### **Simple Explanation of Each Service**

1. **Compute:** Provides virtual machines (VMs) to run applications, software, and workloads.

2. **Object Storage:** Stores files, images, videos, backups, and other unstructured data in the cloud.

3. **Identity Management:** Manages user accounts, permissions, roles, and access to cloud resources.

4. **Key Management:** Creates, stores, and manages cryptographic keys used to encrypt and protect sensitive data.

### **Key Takeaways**

- **AWS:** Known for its wide range of cloud services and mature ecosystem.
    
- **Azure:** Popular among enterprises, especially those using Microsoft products and hybrid environments.
    
- **GCP:** Strong in Kubernetes, data analytics, machine learning, and AI.
    

**Cloud Security Perspective:** As a cloud security professional, understanding IAM, storage permissions, virtual machines, and key management across these three platforms is essential.

# **Cloud Service Models (IaaS, PaaS, SaaS)**

Cloud computing provides services through three main models: **IaaS, PaaS, and SaaS**. Each model offers a different level of control and management to the user.

### **1. IaaS – Infrastructure as a Service**

**Definition:** IaaS provides basic computing infrastructure over the internet, such as virtual machines, storage, and networking.

- Users can create and manage virtual machines.
    
- Users are responsible for managing the operating system, applications, and data.
    
- The cloud provider manages the physical servers and underlying infrastructure.
    

**Examples:**

- AWS EC2
    
- Azure Virtual Machines
    
- Google Compute Engine (GCE)
    

**Simple Example:** Renting a virtual server from AWS instead of purchasing a physical server.

### **2. PaaS – Platform as a Service**

**Definition:** PaaS provides a ready-to-use platform where developers can build, run, and manage applications without managing the underlying infrastructure.

- The cloud provider manages servers, operating systems, and runtime environments.
    
- Developers mainly focus on application development and data.
    
- Reduces infrastructure management work.
    

**Examples:**

- AWS RDS
    
- Azure App Service
    
- Google Cloud Run
    

**Simple Example:** Deploying a web application directly to Azure App Service without manually configuring a server.

### **3. SaaS – Software as a Service**

**Definition:** SaaS provides ready-to-use software applications over the internet. Users can access these applications through a web browser or mobile application.

- No need to install or maintain the underlying infrastructure.
    
- The service provider manages the application and infrastructure.
    
- Users simply access and use the software.
    

**Examples:**

- Microsoft 365
    
- Google Workspace
    
- Salesforce
    

**Simple Example:** Using Gmail or Microsoft Word Online without installing or managing the software infrastructure.

### Cloud Security Study Tip

From a security perspective:

- **IaaS:** You manage OS security, configurations, network security, and applications.
    
- **PaaS:** You mainly manage application security, data, and access permissions.
    
- **SaaS:** You mainly manage user access, account security, and data protection.
    

**Remember:** As we move from IaaS to PaaS to SaaS, the cloud provider manages more of the underlying technology, while the user's control decreases.

# **Cloud Resource Hierarchy & Policy Inheritance**

Cloud Resource Hierarchy defines how cloud resources are organized and managed. It helps organizations manage accounts, projects, users, and resources in a structured way.

It also allows security policies and access permissions to be applied at different levels.

### **Four Levels of Cloud Resource Hierarchy**

**Level 01 – Organization Root**

- The top-level management layer of a cloud environment.
    
- Acts as the central governance boundary for the organization.
    
- Helps manage global billing, security policies, and organizational settings.
    

**Level 02 – OU / Management Group**

- Used to organize different departments or business units.
    
- Groups multiple accounts or subscriptions together.
    
- Allows administrators to apply common security policies to a group.
    

**Level 03 – Account / Project**

- Provides an environment to manage and isolate workloads.
    
- Contains cloud resources such as virtual machines, storage, and databases.
    
- Helps separate different applications, teams, or environments.
    

**Level 04 – Cloud Resources**

- The actual services and resources used by applications.
    
- Includes virtual machines, storage buckets, databases, and networks.
    
- Resources operate within an account or project.

### **Policy Inheritance**

Policy Inheritance means that security policies applied at a higher level can automatically affect the lower levels.

For example:

- A security policy applied at the Organization Root can affect all departments and their accounts.
    
- A policy applied to a specific OU can affect the accounts inside that OU.
    
- Account-level policies can control access to individual cloud resources.
    

**Security Guardrail Rule:**

IAM policies and organizational restrictions, such as AWS Service Control Policies (SCPs), can apply across multiple levels of the hierarchy.

The effective permissions depend on the cloud provider's policy evaluation rules. An SCP, for example, sets permission boundaries in AWS but does not directly grant permissions.

### **Simple Example**

Suppose a company has three departments:

- HR Department
    
- Finance Department
    
- IT Department
    

The organization can apply a security policy at the root level to prevent the use of unauthorized cloud regions. This restriction can then apply to accounts under all three departments.

**Key Takeaway:** Organizing cloud resources into a hierarchy makes it easier to manage access, apply security policies, enforce governance, and maintain security across the entire cloud environment.

# **Security Fundamentals – Securing the Cloud Attack Surface**

**Definition:** Cloud Security focuses on protecting cloud-based infrastructure, applications, data, and services from cyber threats and unauthorized access.

Unlike traditional IT environments, cloud security does not depend only on physical network boundaries. It focuses more on **identity management, access control, data protection, and continuous monitoring.**

### **Traditional Security vs Cloud Security**

**1. Traditional Security (Perimeter-Based Security)**

- Focuses on protecting the internal network using firewalls and network boundaries.
    
- Trust is often given to users and devices inside the network.
    
- Security mainly depends on controlling network access.
    

**2. Cloud Security (Identity-Centric Security)**

- Focuses on verifying users, devices, and applications before granting access.
    
- Uses IAM, MFA, and role-based access control (RBAC).
    
- Continuously monitors cloud resources, activities, and configurations.
    
- Follows the principle of Least Privilege.
    

### **Key Cloud Security Concepts**

1. **Identity-Centric Governance:** Managing and controlling who can access cloud resources and what actions they can perform.

2. **Continuous Visibility:** Continuously monitoring cloud environments to identify suspicious activities, misconfigurations, and security threats.

3. **Attack Surface Management:** Identifying and reducing all possible entry points that attackers could exploit, such as exposed storage, insecure APIs, and misconfigured services.

4. **Access Control:** Ensuring that users and applications receive only the permissions required to perform their tasks.
